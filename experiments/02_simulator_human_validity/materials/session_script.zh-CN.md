# Simulator 有效性研究会话脚本

[English](session_script.md)

## 参与者到场前

- 确认同意书版本与伦理审批；
- 分配匿名参与者代码；
- 验证 Set A 与 Set B 已冻结且互不重叠；
- 验证条件清单和随机 seed 已冻结；
- 在 Git 工作区外打开私有数据位置；
- 确保研究者在 Human Reviewed Map 仲裁期间无法查看后续 Simulator 输出。

## 开场

向参与者说明：本研究评价的是 Simulator，不是参与者。参与者不需要正确回答每个问题。

不确定、部分了解和明确回答“我不知道”都是有价值的数据。

收集任何研究回答前，必须先取得知情同意。

## 阶段 1：Profile Context

执行 `profile_context_questionnaire.csv`，只提出其中列出的追问。

向参与者展示生成的 Profile Context，并允许其修正事实错误。

此阶段不得要求参与者自行分配 L0--L5 掌握度标签。

## 阶段 2：Set A 与 Knowledge Map 审核

按照冻结顺序或预注册的随机顺序呈现 Set A。

除明确标记的转写修正外，应逐字记录参与者回答。

Candidate Knowledge Map 只能依据允许使用的 Set A 数据生成。使用 `human_map_review_form.csv` 审核每个状态。

若参与者与研究者无法在记录理由的前提下解决某个状态，应标记为 `unresolved`，不得强行给出有利标签。

## 阶段 3：留出真人回答

在参与者看到任何 Simulator 回答前呈现 Set B。

除非协议明确允许，提醒参与者不要借助外部搜索。

跳过、超时和“不知道”均应作为结果记录，不得删除。

## 阶段 4：Simulator 生成

按照冻结条件清单运行生成。必须保留每个 seed、fallback、空回答、拒答与解析失败。

准备隐藏条件时参与者不在场。不得展示原始 map、evidence ID、blueprint 或 debug trace。

## 阶段 5：自我忠实度评分

使用冻结的随机化清单。只显示问题、预注册允许时的参与者本人回答，以及一条匿名候选回答。

收集全部十个条目、总体替代判断、偏差标记与可选评论。

所有评分完成前，不得揭示候选回答所属条件。

## 结束

会话结束前，询问参与者是否希望撤回任何自由文本评论。

再次说明退出截止时间与补偿流程。

同意/链接数据必须与回答数据分开保存。应如实记录协议偏离、技术失败和提前退出，不得虚构缺失回答。
