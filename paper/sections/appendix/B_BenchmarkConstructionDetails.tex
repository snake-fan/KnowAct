\section{Benchmark Construction Details}
\label{app:construction}

\subsection{Graph-Authoring Workflow}

The graph-authoring workflow is evidence-first and fail-closed:
\begin{enumerate}[leftmargin=1.7em]
    \item \textbf{Specification.} Authors manually prepare one UTF-8 Markdown source and declare an aspect name and description, representative user tasks, exclusions, a soft target node count, and a hard maximum.
    \item \textbf{Source integrity.} The local catalog records the Markdown file's size and SHA-256 hash; invalid extensions, undecodable content, blank files, and files over the configured size limit are rejected.
    \item \textbf{Deterministic segmentation.} Heading-aware, non-overlapping segments retain their source path, heading path, character count, and source locator.
    \item \textbf{Local extraction.} Each segment is paired with the same scope. The extractor emits thin node drafts with a short exact evidence excerpt, and code verifies that each excerpt occurs in its source segment after whitespace normalization.
    \item \textbf{Global reconciliation and selection.} One global step merges duplicates, adjusts granularity, records supporting draft and segment identifiers, and selects representative skeletons near the target without exceeding the maximum. It may return fewer nodes rather than fill the graph with weak candidates.
    \item \textbf{Independent verification.} A fresh context assigns one keep/remove decision to every skeleton based on source support, scope fit, and diagnostic value. Only supported, in-scope, high- or medium-value nodes continue.
    \item \textbf{Diagnostic enrichment.} Retained skeletons receive goals, mastery rubrics, diagnostic signals, and simulator guidance.
    \item \textbf{Relation authoring and validation.} A precision-first step proposes only typed relations with explicit rationales. Deterministic checks reject invalid endpoints, self-loops, duplicate identifiers, and canonicalization errors.
    \item \textbf{Human review and promotion.} Candidate node and edge lists remain outside the evaluation runtime until reviewers inspect them and an author explicitly promotes an immutable version.
\end{enumerate}

The relation vocabulary includes \texttt{part\_of}, \texttt{prerequisite\_for}, \texttt{supports}, and \texttt{contrasts\_with}. Each label has tests, examples, direction rules, and allowed evidence.

\texttt{prerequisite\_for} denotes a direct dependency: lacking the source concept should normally block stable performance at higher rubric levels of the target. Transitive implications are not emitted as additional edges.

\texttt{part\_of} denotes structural composition. \texttt{supports} denotes a useful but nonessential explanatory or transfer relation. \texttt{contrasts\_with} is stored in a canonical symmetric form.

Rubrics and instructional prerequisite judgments are candidate pedagogical operationalizations, not automatically treated as textbook facts. Their validity is established by human review rather than by structural validation alone.

\subsection{Agent Roles and Decision Independence}

A deterministic orchestrator invokes five bounded model roles: local extractor, global reconciler/selector, independent skeleton verifier, rubric author, and relation proposer. Deterministic code handles segmentation, parsing, evidence membership, budget/provenance checks, and final schema/graph validation.

Roles are logical separation, not a claim that more agents improve quality. Independent prompts and fresh contexts prevent a proposer from validating its own rationale; a different model can be used when resources permit.

Local extraction requests may run concurrently, but results and traces are assembled in source order. Reconciliation is global because the initial narrow slice is intentionally small enough to compare all drafts under one aspect and node budget.

\subsection{Bounded Error Recovery}

The current v1 implementation uses fail-fast, stage-level validation rather than autonomous semantic repair. A provider failure, malformed response, missing or mismatched evidence excerpt, invalid reconciliation provenance, verifier contract violation, node-budget overflow, rubric mismatch, or invalid edge stops downstream execution.

When artifact writing is enabled, completed intermediates and per-step raw/parser traces remain available with a structured workflow log. The benchmark author inspects the failing checkpoint, source evidence, declared scope, and model output, then corrects the input or prompt and starts a new run. The same agent is not allowed to silently rewrite and approve its own invalid item.

This policy favors visible failure over silent corruption. Automatic retry, semantic repair, coverage recovery, and resumable checkpoints are possible extensions, but are not claimed as properties of the current workflow.

\subsection{Expert Review Protocol}

For the initial approximately 20-node graph, two domain experts review every candidate node and edge independently. They resolve disagreements by discussion; a third expert can adjudicate unresolved cases.

Reviewers are recruited from instructors, experienced teaching assistants, and researchers in the target subject. Teaching history and a held-out calibration task establish eligibility.

Review captures item-level accept, edit, and reject decisions with rationales. Node judgments cover source support, aspect fit, granularity, rubric quality, and diagnostic usefulness; edge judgments cover endpoints, type, direction, and rationale. We record reviewer qualifications, review time, and inter-reviewer agreement.

Promotion requires complete machine-checkable provenance, zero unresolved structural errors, and explicit reviewer confirmation. Model verification reduces review load but never replaces expert judgment.

\subsection{Knowledge-Map Review}

Reviewers verify that each candidate map covers every node and that each state is supported by behaviorally realizable evidence.

They also check consistency among mastery, misconceptions, unknowns, profile context, and graph structure. Promotion creates an immutable reviewed snapshot.

\subsection{Manifest-Bound Runtime Contexts}

The runtime maintains three contexts:
\begin{itemize}[leftmargin=1.5em]
    \item \textbf{Tested-agent context:} public graph, interaction rules, visible transcript, and working map.
    \item \textbf{Simulator context:} grounded hidden states, evidence, limited visible dialogue, and optional style context.
    \item \textbf{Evaluation context:} hidden map, final reconstruction, and deterministic scoring configuration.
\end{itemize}

An episode manifest fixes the artifact versions and execution settings shared by these contexts. Debug traces and hidden policy outputs never enter the tested-agent context.
